# Документация разработчика

Подробный разбор проекта для того, кто будет его тестировать и развивать. Если нужно просто поставить расширение и пользоваться — хватит [README.md](README.md).

## 1. История репозитория: что здесь было

**Здесь не было ничего.** Репозиторий `Bumble-helper` создавался под другую идею (автолайкер для Bumble), но до кода дело не дошло: на момент старта работы в нём было **ноль коммитов** — ни файлов, ни истории, ни веток. От прежней задумки не осталось ни строчки, искать и вычищать нечего.

Весь код появился тремя коммитами в ветке `claude/ad-skip-browser-extension-kkdwod`, которая стала веткой по умолчанию (GitHub назначает дефолтной первую запушенную ветку в пустой репозиторий):

| Коммит | Что внутри |
|---|---|
| `c882ceb` | Ядро расширения: манифест, движок, сервис-воркер, попап, иконки |
| `b92cb36` | Фикстура рекламного плеера + e2e-тест на Playwright |
| `95b1917` | README на русском |

Название `Bumble-helper` осталось от старой идеи — его стоит поменять (Settings → General → Rename на `auto-ad-skipper` или `skip-ads`, старые ссылки GitHub редиректит сам). Внутри кода и документации проект уже называется **Auto Ad Skipper**.

Репозиторий **публичный** — читать и клонировать код может кто угодно, но чтобы пушить, нужно быть добавленным в Settings → Collaborators.

## 2. Быстрый старт

```bash
git clone https://github.com/kennylfc8/Bumble-helper.git
cd Bumble-helper
```

Сборка не нужна: это чистые JS/HTML/CSS без npm-зависимостей и без бандлера. Что скачал — то и грузится в браузер.

**Поставить в браузер:** `chrome://extensions` → включить «Режим разработчика» → «Загрузить распакованное расширение» → выбрать папку репозитория (ту, где лежит `manifest.json`). После правки кода жать «Обновить» (↻) на карточке расширения и перезагружать страницу с плеером.

**Прогнать тесты** (нужен Node и Playwright; в контейнере разработки он глобальный):

```bash
NODE_PATH=/opt/node22/lib/node_modules node test/run-e2e.cjs
```

Ожидаемый результат — `OK: все проверки прошли.` Если Playwright установлен локально (`npm i -D playwright`), префикс `NODE_PATH=` не нужен.

## 4. Как это работает

### 4.1. Четыре независимых куска кода

Расширение живёт в четырёх разных средах, и это главное, что нужно понять перед чтением кода:

| Где | Файл | Что видит | Отладка |
|---|---|---|---|
| **Изолированный мир каждого фрейма** | `content/engine.js` + `patterns.js` | DOM страницы, но не её JS-переменные | Консоль вкладки (F12) |
| **Главный мир страницы** | `content/page-guard.js` | JS-объекты самой страницы (`window.open`) | Консоль вкладки |
| **Сервис-воркер** | `background.js` | Вкладки, хранилище; DOM не видит | `chrome://extensions` → «service worker» |
| **Попап** | `popup/popup.js` | Своя маленькая страница | Правый клик по попапу → «Просмотреть код» |

Ключевой момент: `engine.js` запускается **в каждом фрейме отдельно** (`all_frames: true`), включая вложенные кросс-доменные iframe плееров. У каждого экземпляра своё состояние; они друг о друге не знают, а координирует их только сервис-воркер. Реклама почти всегда живёт именно во вложенном iframe, поэтому расширение, работающее только на верхней странице, до неё бы не достучалось.

Второй момент: `page-guard.js` — единственный код в «главном мире». Он нужен только для подмены `window.open`, потому что из изолированного мира до настоящей функции страницы не дотянуться. Всё остальное (чтение DOM, мут видео, клики) прекрасно делается из изолированного мира.

### 4.2. Жизненный цикл фрейма

1. **Старт** (`document_start`, до отрисовки страницы). Фрейм спрашивает у сервис-воркера контекст сообщением `GET_CTX` и получает `{topHost, settings}`. Хостнейм верхней страницы нужен, потому что кросс-доменный iframe сам его узнать не может, а настройка «отключить на этом сайте» привязана именно к верхнему сайту. Если воркер спит, запрос повторяется до 4 раз с нарастающей паузой.
2. **Парковка.** Если расширение выключено глобально или для этого сайта — фрейм не делает ничего, только слушает изменения настроек, чтобы «проснуться». Никаких наблюдателей и таймеров.
3. **Наблюдение.** Иначе вешается `MutationObserver` на весь документ (изменения детей, а из атрибутов — `class`, `style`, `disabled`, `aria-disabled`, `hidden`). Сканирование дебаунсится на 250 мс, так что шквал изменений от SPA-плеера превращается в одно сканирование.
4. **Страховочный таймер.** Раз в секунду сканирование запускается принудительно — но **только если** во фрейме есть видео/аудио или это домен рекламной сети. На обычных страницах таймера нет вообще: висит один наблюдатель, который почти ничего не стоит.
5. **Реклама найдена** → «горячий» режим: сканирование каждые 200 мс, чтобы поймать момент, когда кнопка станет активной.
6. **Реклама кончилась** → возврат к ленивому режиму.

### 4.3. Детекция рекламы: три яруса и формула

Файл `content/patterns.js`, функция `scan()` в `engine.js`.

**Ярус A — домен фрейма.** Если сам фрейм загружен с домена рекламной сети (`doubleclick.net`, `an.yandex.ru`, `adfox.ru`, `buzzoola.com` и ещё десяток), это почти наверняка реклама.

**Ярус B — селекторы известных рекламных движков.** Классы, которые реально используют Google IMA/VAST (`.videoAdUi`, `.videoAdUiSkipButton`), video.js-ima, JW Player (`.jw-ad`, `.jw-skip`) и типовые VAST-обёртки. Считаются только **видимые** элементы. Слишком общие селекторы вроде `[class*="adv_"]` учитываются только внутри фреймов яруса A — иначе будут ложные срабатывания на пол-интернета.

**Ярус C — текст кнопок.** Нормализованный текст (обрезка, схлопывание пробелов, нижний регистр, максимум 60 символов) прогоняется через регэкспы: «Пропустить рекламу» / «Пропустити рекламу» / «Skip Ad» — сильный сигнал; голое «Пропустить» / «Skip» — слабый; «Пропустить заставку/интро/титры» — **стоп-лист**, такое не трогаем никогда.

Дальше из этих ярусов собираются четыре сигнала, и решение принимается формулой (`engine.js`, функция `scan`):

```js
adActive =
  (s1 && (есть медиа || s2 || есть кандидат))   // мы внутри рекламного домена
  || s2                                         // на экране рекламный контейнер
  || (сильный кандидат && (есть медиа || s4))   // «Пропустить рекламу» рядом с видео
  || (слабый кандидат && есть медиа && (s4 || таймер видели недавно));
```

где `s1` — рекламный домен, `s2` — видимый рекламный контейнер, `s4` — бейдж «Реклама» рядом с видео.

Смысл формулы — **не трогать нормальные сайты**. Голая кнопка «Skip» в форме регистрации не даст ничего: нет ни видео, ни бейджа, ни таймера. Именно это проверяется в тестах декоями.

### 4.4. Заглушение: два слоя

Слой 1 — **мут вкладки** (`background.js`). Пока хоть один фрейм сообщает «идёт реклама», вкладка глушится через `chrome.tabs.update({muted: true})`. Это гарантия: ловит даже звук через WebAudio и из фреймов, которые движок не распознал.

Слой 2 — **мут самих `<video>`/`<audio>`** в рекламном фрейме. Срабатывает мгновенно, в том же цикле, что и детект, без пересылки сообщений — поэтому даже если сервис-воркер спал, первые миллисекунды рекламы уже беззвучные. Прежние `muted`/`volume` каждого элемента запоминаются в `WeakMap` и возвращаются после рекламы.

Две тонкости, о которые легко споткнуться при доработке:

- **Чужой мут не трогаем.** Перед тем как глушить вкладку, воркер смотрит `tab.mutedInfo`. Если вкладка уже замучена — считаем, что это сделал пользователь, и не размучиваем её потом никогда. Размут происходит только если `mutedInfo.reason === 'extension'` и id расширения наш.
- **Пауза перед размутом — 1.5 секунды.** Между роликами цепочки есть доля секунды тишины; без задержки пользователь ловил бы «пшик» звука второй рекламы. Поэтому размут отложенный, и если реклама возвращается — он отменяется.

### 4.5. Пропуск: как понять, что кнопку уже можно нажать

Это самая тонкая часть. Кнопка «Пропустить» существует в DOM задолго до того, как её можно нажать, — сначала висит таймер. Клик раньше времени плеер проигнорирует, а некоторые ещё и накажут перезапуском ролика.

Функция `clickabilityIssue()` возвращает `null`, только если пройдены **все** проверки, иначе — причину отказа (она же попадает в отладочный лог):

| Проверка | Причина в логе |
|---|---|
| Элемент ещё в документе | `detached` |
| Не `disabled` / не `aria-disabled="true"` | `disabled`, `aria-disabled` |
| Не внутри `aria-hidden` контейнера | `aria-hidden` |
| Размер хотя бы 4×4 пикселя | `no-box` |
| `display`, `visibility`, `opacity` в порядке | `hidden`, `transparent` |
| `pointer-events` не `none` (наследуется — заодно проверяет родителей) | `pointer-events` |
| В тексте нет таймера («через 5 сек», «in 5s») | `countdown` |
| `elementFromPoint` в центре кнопки возвращает её саму, потомка или предка | `off-viewport`, `overlaid` |

Последняя проверка — защита от невидимого оверлея поверх кнопки: если в точке клика лежит что-то постороннее, значит реальный клик мыши тоже не дошёл бы.

**Лестница кликов.** Плееры по-разному слушают события, поэтому попытки идут по нарастающей, по одной за раз, с проверкой результата через 800 мс:

1. Полная последовательность как у настоящей мыши: `pointerover → pointerenter → mouseover → mousemove → pointerdown → mousedown → pointerup → mouseup → click`, с координатами центра кнопки. Большинству плееров нужно именно это, а не голый `click`.
2. Обычный `element.click()` — иногда обработчик висит на `onclick` и ловит только его.
3. Ретаргет: тот же полный клик, но по элементу, который реально лежит в точке (бывает, что текст в `<span>`, а обработчик — на обёртке).

**Проверка результата:** через 800 мс смотрим, исчезла ли кнопка или реклама. Исчезла — считаем пропуск удавшимся, увеличиваем счётчик, остаёмся «горячими» ради следующего ролика. Нет — следующая ступень лестницы. После трёх неудачных раундов кнопка уходит в чёрный список на 10 секунд, чтобы не долбить её вечно. Плюс общие лимиты: не чаще одного клика в 700 мс и не больше 30 в минуту на фрейм.

### 4.6. Заслонка от попандеров

Некоторые сайты вешают на первый клик по плееру открытие мусорной вкладки. Поэтому перед каждым нашим синтетическим кликом `engine.js` синхронно бросает событие `__aas_guard`, а `page-guard.js` в главном мире на 1.8 секунды подменяет `window.open` заглушкой, которая возвращает фиктивное «уже закрытое» окно. Через 1.8 секунды всё возвращается: собственные попапы сайта по клику пользователя работают как обычно.

Событие используется именно `dispatchEvent`, а не `postMessage`, потому что первое проходит между мирами синхронно — заслонка гарантированно взведена до клика.

### 4.7. Обмен сообщениями

| Сообщение | Направление | Зачем |
|---|---|---|
| `GET_CTX` | фрейм → воркер | Узнать хост верхней страницы и настройки |
| `AD_STATE {active}` | фрейм → воркер (через Port) | Реклама началась/кончилась → мут вкладки |
| `SKIPPED` | фрейм → воркер | Увеличить счётчик и бейдж |
| `GET_TAB_COUNT` | попап → воркер | Показать счётчик по вкладке |

`AD_STATE` идёт через долгоживущий `Port`, а не разовым сообщением, не просто так: если рекламный iframe умрёт посреди ролика, порт разорвётся сам, и воркер поймёт, что рекламы больше нет. Иначе вкладка осталась бы замученной навсегда.

### 4.8. Хранилище

| Ключ | Где | Что |
|---|---|---|
| `settings` | `storage.local` | Все настройки (см. таблицу в README) |
| `stats` | `storage.local` | `{ totalSkipped, perHost }` |
| `mutedTabs` | `storage.session` | Какие вкладки замутили мы — чтобы пережить перезапуск сервис-воркера |

Настройки и статистика лежат в **разных ключах** намеренно: попап и воркер пишут туда одновременно, и общий объект они бы затирали друг другу. Все изменения настроек разъезжаются по фреймам через `chrome.storage.onChanged` — отдельная рассылка не нужна.

## 5. Как отлаживать на реальном сайте

Если на каком-то сайте реклама не пропускается:

1. Открой попап и включи **«Отладочные логи»**.
2. Открой консоль (F12) на странице с плеером и в фильтре включи уровень **Verbose** — иначе `console.debug` не видно.
3. Перезагрузи страницу и запусти серию. Сообщения помечены `[AAS]` и именем фрейма.

Что означают сообщения:

| Сообщение | Диагноз |
|---|---|
| `unparked` | Движок запустился в этом фрейме |
| `parked` | Выключен глобально или для сайта |
| *(тишина)* | Скрипт вообще не попал во фрейм |
| `ad detected` / `ad over` | Реклама распознана / закончилась |
| `no skip candidates` | Реклама видна, но кнопку не нашли → нужен адаптер (см. ниже) |
| `candidate not clickable (countdown)` | Кнопка найдена, честно ждём конца таймера — это норма |
| `candidate not clickable (overlaid)` | Кнопку перекрывает что-то сверху |
| `candidate not clickable (pointer-events)` | Кнопка или её родитель не принимают клики |
| `clicked skip, round 0/1/2` | Кликнули; номер — ступень лестницы |
| `skip confirmed` | Пропуск удался |
| `candidate blacklisted` | Три попытки не сработали, пауза 10 секунд |

**Если `no skip candidates`** — найди кнопку в инспекторе, посмотри её класс и добавь адаптер в конец `content/patterns.js`:

```js
const ADAPTERS = {
  'animesite.example': {
    skipSelectors: ['.player-skip-btn'],   // сама кнопка пропуска
    adSelectors: ['.player-ad-overlay'],   // контейнер рекламы (необязательно)
  },
};
```

Ключ — хостнейм **верхней страницы** (то, что в адресной строке), даже если кнопка живёт во вложенном iframe. После правки: обновить расширение на `chrome://extensions` и перезагрузить страницу.

**Если кнопка нажимается, но плеер не реагирует** — вероятно, ему нужен «доверенный» клик от настоящей мыши. Синтетические клики такими не бывают; обойти это можно только через `chrome.debugger`, что сознательно не сделано (требует пугающего разрешения и показывает жёлтую плашку «расширение отлаживает браузер»).

## 6. Тесты

`test/run-e2e.cjs` поднимает локальный сервер с фикстурой, запускает Chromium с загруженным расширением и проверяет реальное поведение.

Фикстура (`test/fixture/`) имитирует типичный пиратский плеер, не требуя ни видеофайлов, ни интернета: картинка рисуется на `<canvas>` и превращается в видеопоток, звук — генератор тона. Верхняя страница открывается как `localhost`, а iframe с «рекламой» — как `127.0.0.1`; для браузера это **разные источники**, так что тест реально проходит кросс-доменный путь, а не упрощённый.

Что разыгрывается по сценарию:

1. **Реклама 1** в стиле Google IMA: оверлей `.videoAdUi` и кнопка `.videoAdUiSkipButton`, появляющаяся через 3 секунды.
2. **Реклама 2** через 0.7 секунды после первой (проверка цепочки и паузы перед размутом): текстовая кнопка «Пропустить рекламу (через 3 сек)» с тикающим таймером. Клик до нуля фиксируется как **преждевременный** и валит тест.
3. **Ловушка-попандер**: первый же клик в фрейме зовёт `window.open`.
4. **Декои** на верхней странице: «Пропустить заставку» и «Skip» в форме — их трогать нельзя.
5. **Контентное видео** верхней страницы, которое не должно быть замучено.

Проверяется: обе рекламы пропущены; мут за ≤ 800 мс; первая реклама пропущена за ≤ 6 с; ноль преждевременных кликов; ноль попандеров и заслонка подтверждена; звук восстановлен; декои не кликнуты; контентное видео не замучено; попап открывается без ошибок и показывает счётчик `2`.

Флаги:

```bash
node test/run-e2e.cjs --serve-only     # поднять фикстуру и посмотреть глазами в браузере
AAS_DEBUG=1 AAS_VERBOSE=1 node ...     # логи движка прямо в вывод теста
AAS_HEADFUL=1 xvfb-run -a node ...     # если headless с расширением не заводится
```

**Чего тест не покрывает** (проверять руками): мут на уровне вкладки — Playwright его не видит; реальные сайты; переживание перезапуска сервис-воркера; попап как интерфейс (кликами). Ручной чеклист — в конце README.

## 7. Грабли, на которые уже наступили

- **`\b` в регэкспах не работает с кириллицей.** Это был настоящий баг: `/skip ad\b/i` отлично матчил английский, а «Пропустить рекламу» — нет, потому что `\b` в JavaScript знает только латиницу, цифры и подчёркивание. Из-за этого вторая реклама в тестах не пропускалась. Границы слов теперь пишутся явными lookahead'ами (`(?!${W})` в `patterns.js`). **Если добавляешь регэксп с кириллицей — не используй `\b`.**
- **Сервис-воркер в MV3 засыпает** через ~30 секунд бездействия. Нельзя хранить состояние в его памяти и надеяться, что оно доживёт: то, что важно, зеркалится в `storage.session`, а фреймы умеют переподключать порт.
- **Расширения не работают в `chromium_headless_shell`** — нужен полный бинарник Chromium, поэтому в тесте явно задан `executablePath`.
- **Каждый фрейм — отдельный экземпляр движка.** Переменная, заведённая «на страницу», на деле окажется у каждого iframe своя. Общее состояние — только через сервис-воркер.
- **Мутить надо и `<audio>`, и `<video>`**, и делать это заново для элементов, появившихся уже во время рекламы: плееры любят пересоздавать теги.

## 8. Что делать дальше (по убыванию пользы)

1. **Обкатать на реальных сайтах.** Самое ценное сейчас. Прогнать 5–10 сайтов, для упрямых — собрать адаптеры. Каждый адаптер это 3 строки данных в `patterns.js`, менять движок не нужно.
2. **Расширить списки в `patterns.js`** новыми рекламными доменами и селекторами по мере находок.
3. **Версия для Firefox.** Код почти совместим; отличается манифест (там свои правила для MV3 и `world: "MAIN"`). Понадобится отдельный `manifest.firefox.json` и мелкая проверка API.
4. **Страница настроек** (`options_page`) — попап тесноват, если настроек станет больше; заодно место для управления списком сайтов и адаптерами через интерфейс.
5. **Локализация** через `_locales` — если планируется публикация в магазине, английский интерфейс обязателен.
6. **Подготовка к Chrome Web Store:** скриншоты, промо-картинки, политика приватности (у нас простая — данные не собираются и никуда не отправляются), обоснование разрешения `<all_urls>` для ревью. Учти: Google не даёт продавать расширения напрямую с 2021 года — монетизация только через внешнюю оплату.
7. **Юнит-тесты на регэкспы** отдельно от e2e — сейчас они проверяются только через полный прогон браузера, а это медленно.

## 9. Как вести разработку

- Ветка `claude/ad-skip-browser-extension-kkdwod` — основная (она же дефолтная). Для заметных изменений лучше отводить свою ветку и делать pull request, для мелких правок адаптеров можно коммитить прямо в неё.
- **Перед каждым коммитом гоняй e2e** — он ловит именно те регрессии, которые глазами не видно (преждевременные клики, потерянный размут, случайные клики по декоям).
- Стиль: чистый JS без зависимостей, `'use strict'`, комментарии — там, где объясняют «почему так», а не «что делает строка». Добавление зависимости или сборщика сломает главное свойство проекта: папку можно просто загрузить в браузер как есть.
- `test/.profile/` — временный профиль браузера от тестов, он в `.gitignore`, коммитить его не надо.
